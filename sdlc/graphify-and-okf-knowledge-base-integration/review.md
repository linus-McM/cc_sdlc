## Security
- Important: scripts/sdlc/knowledge.py:242 `[knowledge] bundle` was interpolated unescaped into the generated post-commit block (inside a single-quoted grep pattern) and used as an unvalidated path, so a tracked `.sdlc.toml` could plant shell that runs on every commit. Addressed: `cfg()` rejects any `bundle` outside `[A-Za-z0-9._/-]` or containing `..`, absolute or trailing `/`, with a `Blocked`; the plugin path is written through `shell_word` (backslash, `"`, `$`, backtick escaped); `test_bundle_setting_is_validated_before_it_reaches_a_hook_or_path`.
- Important: hooks/hooks.json:4 the SessionStart prelude ran `curl ... | sh` on any machine without uv regardless of `[knowledge] enabled = false` or `SDLC_KNOWLEDGE=off`. Addressed: the prelude installs only when neither switch is off (env check plus a grep of `.sdlc.toml`), then runs the hook through uv when present and `python3` otherwise. The install itself stays, as the product owner asked; it is POSIX-shell only because Claude Code runs hook commands through sh.
- Important: hooks/hooks.json:7 every per-call hook ran only through `uv run`, so without uv, offline, or past the 10 s timeout the pre-edit and pre-bash guardrails failed open. Addressed: each command is `if command -v uv; then exec uv run --no-project "$P" <event>; else exec python3 "$P" <event>; fi`; `test_hooks_json_registers_session_start_and_post_bash`.
